# 0. One world, four entrances

These are not four unrelated websites and should not become four templates with different colors.

They are four entrances into one world:

```text
                              MingOS
                         mingos.cn · the idea
                               /     \
                              /       \
                             /         \
                    Family Space       归
                     ymai.love       ymai.fun
                      for us           for me
                             \         /
                              \       /
                               \     /
                               月明
                              ymai.me
                         where it began
```

Only one mother brand needs to carry the full world: **MingOS**.

- **Family Space** is one real place where MingOS meets the relationship between people closest to one another.
- **Return to Oneself / 归** is one real place where MingOS meets the relationship between a person and themselves.
- **ymai.me** is not a product tier. It is the origin record: where the questions came from, what was tried, what failed, and why MingOS exists at all.

The four sites share an experience constitution, not a page template.

---

# 1. Shared narrative rule

Every site must move in this order:

```text
felt reality
→ a question or absence
→ a space opens
→ only then explain the product/system
→ show what is real
→ allow the person to continue or leave
```

Never reverse it into:

```text
architecture
→ feature list
→ company claims
→ generic use cases
→ CTA wall
```

The visitor should not be required to understand MingOS terminology before they can feel why the place exists.

---

# 2. Shared cross-site navigation

## 2.1 Default navigation

The persistent navigation should be deliberately small.

Left:

```text
MingOS  ○
```

Right, only what the current site needs.

The open circle is a **prototype navigation marker**, not a finalized logo.

## 2.2 World switcher

Selecting `MingOS ○` may open a quiet world switcher:

```text
MingOS
The idea

Family Space
For us

归 · Return to Oneself
For me

月明
Where it began
```

Avoid corporate category labels such as `Products / Solutions / Company / Resources` unless a later information need genuinely requires them.

## 2.3 Cross-site rule

Cross-site links must feel like moving between places, not upselling between products.

No site should become a funnel that forces the visitor through every other site.

# 3. `mingos.cn` — the front door

## Role

`mingos.cn` lets a person encounter the question MingOS is working on, see two real directions where the work touches life, and inspect the evidence and boundaries if they want to go deeper.

It is not primarily a product catalogue, technical docs landing page, or startup pitch.

## What should remain after ten minutes

> **原来技术和一个人之间，还可以有另一种关系。**

## Time character

Slow. Spacious. Deliberate.

The page should not hurry the visitor into a CTA.

## Primary action

**Continue / inspect what is real.**

No forced sign-up.

---

## Homepage act structure

### ACT 01 — Presence

Screen is almost empty.

```text
MingOS

当智能越来越靠近我们的生活，
我们开始认真想一件事：

技术和一个人之间，
还可以是什么关系？
```

Small continuation cue:

```text
往下
```

No feature list. No AI graphic. No “Get Started”.

### ACT 02 — We do not begin with an answer

```text
我们不知道最后的答案。

所以先从真实的生活开始。
```

Then two small fragments of reality appear, not product names yet:

```text
一个家，最近总在晚上因为作业吵起来。

一个人，听见了很多关于未来的建议，
却越来越不知道哪一个是自己的声音。
```

The visitor should understand the scale: ordinary life, not abstract “humanity”.

### ACT 03 — Two places

The two fragments open into two distinct places.

#### Family Space

```text
Family Space

世界没有给一个家庭留一个地方。
我们想留一个。

不是为了把一家人分析得更彻底。
而是让发生过的生活有地方留下，
让不同的人可以被分别看见，
让一些当时看不懂的事情，后来有机会重新理解。
```

Link:

```text
去 Family Space
```

#### 归 · Return to Oneself

```text
归
Return to Oneself

世界有太多声音。
这里，留给你自己的声音。

不是替你找到“正确的人生”。
只是让外面的声音先安静一点，
看看此刻真正属于你的问题是什么。
```

Link:

```text
去「归」
```

### ACT 04 — The shared order underneath

Only now introduce MingOS as a system.

```text
它们看起来不同。

但背后，我们正在尝试守住同一种秩序。
```

Then a sparse sequence:

```text
先看见发生了什么。

再区分事实、感受、理解和还不知道的部分。

可以记住，也必须可以修正和忘记。

AI 可以给出一种理解，
但不能静默拿走人的最终判断。

有时候，最好的下一步是什么都不做。
```

Then:

```text
这套可运行、可检查、可修订的共同秩序，
我们叫它 MingOS。
```

Technical readers get a secondary link:

```text
查看系统与协议 →
```

### ACT 05 — What cannot be traded away

Introduce Foundation without architecture theatre.

```text
如果系统有一天比今天强很多，
有些东西仍然不能因为“更智能”就被拿走。
```

Six concise boundaries:

- 人不是待优化的对象。
- 事实不能被解释冒充。
- 不知道可以继续是不知道。
- 重要记忆应当可见、可修正、可退出。
- 系统不能静默取得人的最终决定权。
- 明确安全风险需要独立、可审查的保护边界。

Then:

```text
Ming Foundation 负责把这些边界留住。
```

Link:

```text
查看 Foundation →
```

### ACT 06 — Reality, not promise

A public evidence surface.

Heading:

```text
我们现在真正做到哪里
```

Use status markers:

```text
EXISTS
What exists now

TESTING
What is being tested now

DIRECTION
What is only a direction

UNKNOWN
What we still do not know
```

The data must be sourced from current repository/deployment facts at release time. No static claim in this story brief should be copied into production without verification.

A timestamp is mandatory.

### ACT 07 — Open questions

Heading:

```text
还有一些问题，我们没有答案。
```

Possible questions:

- 长期 AI 记忆怎样在真正有用的同时，不慢慢变成人的另一种枷锁？
- 一个家庭里，共同记忆属于谁？
- 当几个人对同一件事有不同理解时，系统应该怎样保持边界？
- AI 什么时候应该继续，什么时候应该闭嘴？
- 当一个人越来越依赖智能系统，我们怎样知道“帮助”有没有开始变成“替代”？

This section should remain editable as real work evolves.

### ACT 08 — Close without conquest

No launch theatre.

```text
我们还很早。

不知道它最后会长成什么样。

所以不先定义一个宏大的未来。

先把另一种可能，
一点点做出来。
```

Footer links:

- Family Space
- 归
- Foundation / technical work
- 月明 / origin
- GitHub where publicly appropriate

Final line may be:

```text
Technology on the side of life.
```

This is a secondary signature, not a repeated marketing slogan.

# 4. `ymai.love` — Family Space

## Role

A place that feels like it belongs to a family, not a console a family visits to consult an AI.

## What should remain after ten minutes

> **原来一个家真的可以有一个自己的地方。**

## Time character

Everyday time: today, recently, this year, what happened and what was later understood.

## Primary action

```text
进入我的家
```

## First-screen story

Use authentic family-life photography only when such material exists and has permission. Until then, use typography rather than stock happiness.

```text
Family Space

世界没有给一个家庭留一个地方。

我们想留一个。
```

Secondary line, only after the pause:

```text
不是等出了问题才来。
生活本身，就值得有地方留下。
```

## Product demonstration principle

Do not explain the product through a feature grid.

Show one ordinary day:

```text
07:18
早上孩子不太想说话。

17:42
妈妈记下老师今天的一句话。

20:16
因为作业吵了一架。

21:03
爸爸觉得自己刚才说得太重。

三个月以后
一家人重新看这段时间，
才发现那阵子大家都很累。
```

The product capabilities—recording, memory, multiple perspectives, revision, reflection—should be understood through the life sequence.

## Product home direction

Do not default to a chatbot screen.

A future product home may begin:

```text
晚上好。
8 月 27 日 · 星期四

今天这个家留下了：
3 件小事
1 段对话
1 件还没有说完的事

今天怎么样？
```

Primary entries:

- `记下一件事`
- `有件事想聊聊`
- `看看最近`

Possible place names:

- `今天`
- `我们家`
- `我的地方`
- `时光`
- `回望`

These are product-owned navigation candidates, not MingOS Core vocabulary.

## Critical experience obligations

Family Space must eventually prove in real UI:

- shared and private space are unmistakably different;
- different family members are not collapsed into one truth;
- record/pattern/interpretation/suggestion are distinguishable when it matters;
- memory is inspectable and correctable;
- AI does not need to reply to every record;
- no family score pretends to summarize a relationship;
- a useful interaction can end by returning to family life.

# 5. `ymai.fun` — 归 · Return to Oneself

## Role

A place where outside noise can quiet enough for a person to hear what is actually theirs.

It must not become a therapy aesthetic, growth dashboard, productivity system, or gamified self-improvement product.

## What should remain after ten minutes

> **这里没有替我找答案，但我好像更听得见自己了。**

## Time character

Present time.

Not “your life progress”. Not performance history. Begin from now.

## Primary action

```text
从现在开始
```

## First-screen story

```text
最近，
你有听见自己的声音吗？
```

Then outside voices appear, one at a time:

```text
应该再努力一点。

别人都已经……

这个选择更稳妥。

你应该成熟一点。

机会不能错过。

你怎么还不知道自己想做什么？
```

They recede.

Then:

```text
如果这些声音先安静一下呢？
```

Reveal:

```text
归
Return to Oneself

世界有太多声音。
这里，留给你自己的声音。
```

## Beginning interaction candidate

```text
此刻，你更接近哪一种？
```

- `有点乱`
- `不知道`
- `有件事放不下`
- `我有个想法`
- `挺好的`
- `什么都不想说`

The presence of `挺好的` and `什么都不想说` matters: the place must not imply that a person needs to be broken in order to enter.

## Explicit prohibitions for the default experience

No default:

- growth score;
- mental-health score;
- streak;
- XP;
- level;
- ranking;
- “you are ahead of 78% of users”;
- identity label derived from interaction history;
- forced daily reflection.

## Motion character

This can be the most experimental of the four sites, but motion must carry meaning:

- outside voices gather and recede;
- a person’s own sentence becomes clearer;
- AI text may recede after it has helped;
- the final visual emphasis belongs to the user’s words, not the assistant’s answer.

# 6. `ymai.me` — 月明 / Origin Record

## Role

Not “About the founder”. Not a résumé in website form.

It is the origin record of why this work exists and how it changed.

## What should remain after ten minutes

> **原来这些东西不是从一个 AI 创业概念长出来的。**

## Time character

Lived time: before AI → family practice → unresolved questions → experiments → mistakes → FamilyOS → MingOS → today.

## Primary action

```text
继续读
```

No aggressive partnership or sales CTA on the first screen.

## First screen

```text
月明

我不是从 AI 开始的。

这些年，我一直在和真实的家庭待在一起。
后来开始学习 AI。

最后发现，
我真正关心的一直是同一件事：

人怎样成为他自己。
```

## Narrative route

### Before AI

Real work with families. What was repeatedly seen that existing systems did not hold well.

### Questions that stayed

Not a list of credentials. A record of unresolved realities.

### AI appeared

Why the technology changed what was possible—not because it was fashionable, but because experience could begin to become a revisable, running system.

### FamilyOS → MingOS

Show names, abandoned approaches, wrong assumptions, screenshots, commits, notes, and revisions where appropriate.

### Today

What is actually being built now. What remains uncertain.

## Archive material

Over time, ymai.me may contain:

- old notes;
- rejected designs;
- early screenshots;
- articles;
- commit fragments;
- dated decisions;
- “I was wrong” entries;
- real public feedback with permission;
- the evolution of the core question.

The value should increase with time because the site keeps provenance rather than polishing history into a founder myth.

# 7. Shared visual relationship

The sites should feel like **four letters written by the same hand**, not one template skinned four ways.

Shared:

- typography discipline;
- spacing logic;
- Open Form principle;
- motion physics;
- accessible interaction;
- evidence/status semantics;
- restrained color;
- language ethics;
- performance standards.

Distinct:

- pacing;
- composition;
- image role;
- amount of interaction;
- density;
- emotional temperature;
- dominant time scale.

---

# 8. First implementation decision

The first reference implementation is `mingos.cn`.

Reason:

1. It has to establish the shared world without being a product dashboard.
2. It can establish typography, layout, motion, evidence markers, navigation, performance, and accessibility before downstream product UI inherits them.
3. The current `YuemingHub/MingOS` repository has no mature web application that must be preserved, so an isolated prototype can be added without pretending to be production.
4. The prototype must remain clearly separated from MingOS Core semantics.

V1 prototype path:

```text
web/prototype-v1/
```

V1 goals:

- real HTML/CSS/JS in a browser;
- no framework dependency required to inspect the narrative;
- responsive from mobile upward;
- reduced-motion support;
- no stock imagery;
- no analytics;
- no form capture;
- no claim that prototype content is production fact unless sourced at build/release time.

---

# 9. Prototype acceptance test

The first `mingos.cn` prototype is not accepted because it looks polished.

It passes only if reviewers can answer yes to these questions:

1. Can someone understand why this place exists before seeing architecture?
2. Does the page avoid fear and urgency as persuasion?
3. Does it avoid proving how impressive MingOS is?
4. Can Family Space and Return to Oneself be understood through ordinary life rather than feature lists?
5. Does MingOS appear as an underlying order, not a giant AI persona?
6. Is Foundation introduced as boundary, not bureaucracy?
7. Is the distinction between current reality, testing, direction, and unknown visible?
8. Are open questions allowed to remain open?
9. Is there a natural end without a conversion trap?
10. On mobile, does the experience remain calm, readable, fast, and complete?

If the result feels like “a very good AI startup website”, it is not done.

The intended reaction is closer to:

> **“我不知道该把它归在哪一类，但我知道它在尝试一种不同的东西。”**
